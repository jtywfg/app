# PinPic：拼图、照片编辑、证件照与文档扫描

PinPic 是一款以本机处理为主的移动端图片工具，适合日常照片分享、长图制作、电子证件照处理及纸质文档扫描。当前提供免费使用的业务流程，无需注册登录或购买 VIP；本地照片的编辑、人像背景替换、扫描识别与图片保存不依赖业务后端。

本文面向两类读者：安装 APK 的使用者可以了解入口、操作方法及作品保存位置；开发人员可以了解页面组织、数据流、原生模块、素材维护和打包验证方式。

> 文档根据 2026-10-14 的当前源码整理。应用配置版本为 **1.1.4**，Android `versionCode` 为 **14**，应用名称为 **PinPic**，包名为 `com.pinpic.app`。`mixoo-v1` 是项目目录名称，部分相册标签保留了 MIXOO 字样。源码功能说明不等同于某个旧 APK 已包含全部功能，实际使用应核对安装版本。

## 1. 业务入口与当前范围

首页上方提供「快速拼图」「编辑」「扫描」三个主要入口；下方提供「布局」「长图拼接」「自由拼图」「九宫格」「格子拼图」。左上角可以进入设置，设置中包含「我的拼图」。

首页「热门」区域提供六个工具：一寸照、二寸照、更多规格、证件照换底色、修改文件 kb 大小、修改文件 px 尺寸。

| 功能 | 当前业务能力 | 输入与主要输出 |
| --- | --- | --- |
| 快速拼图 | 按照片数量预览布局、调整画布及组合效果 | 2–9 张照片 → 一张 JPEG 拼图 |
| 编辑 | 裁剪、基础滤镜与调整、可移动文字和贴纸 | 一张照片或拍照 → 一张 JPEG |
| 布局 | 大幅预览与底部布局缩略图对比，进入共同拼图编辑器 | 2–9 张照片 → 一张 JPEG 拼图 |
| 自由拼图 | 每张照片独立移动、缩放和旋转，允许重叠摆放 | 2–9 张照片 → 一张 JPEG 拼图 |
| 长图拼接 | 按选择顺序纵向拼接，保留各图比例，支持整体预览 | 2–20 张照片 → 一张 JPEG 长图 |
| 九宫格 | 单图取景调整，分为 3、6、9 或 12 格，单张或全部保存 | 一张照片 → 多张 JPEG 小图 |
| 证件照 | 选规格、拍照/选图、人脸检测、自动取景、换底色、轻度修饰、正装叠加 | 单人人像 → 电子照或排版照 |

| 扫描 | 智能识边、书籍分割、透视裁切、图像增强、多页导出 | 拍照/相册导入 → PDF、Word、长图或相册图片；目前原生引擎仅 Android |
| 我的拼图 | 查看相册作品、大图预览、选择删除 | 系统相册中的成品图片 |
| 格子拼图 | 首页占位，提示后续推出 | 尚无编辑流程 |
| 购买/会员图标 | 展示免费版说明 | 尚无支付、订阅或会员权益流程 |

「最新」「拼贴」「动图」「国庆节」「旅行」目前展示本地示意卡片，点击后进入快速拼图；没有独立的在线模板商城、节日模板库或动图输出引擎。快速拼图页面中的「主题模板」文字也不代表已实现独立主题模板业务。

## 2. 安装与首次使用

### 2.1 Android APK

当前工作区父目录有 `PinPic-1.1.4.apk`，即 `/Users/mac13/ai/pinpic/PinPic-1.1.4.apk`。它是本地安装文件，不随 Git 源码默认提交。

将 APK 传到手机后，使用系统文件管理器打开并安装；如系统要求，允许该文件管理器安装应用。覆盖安装需要包名及签名与已安装版本一致，并满足 Android 的版本要求。新的业务代码或素材只有在重新打包、安装对应 APK 后才会生效。

安装后的独立 APK 可以脱离开发电脑运行。通过开发服务器运行的项目则需要开发环境，不能据此判断安装版的离线能力。

### 2.2 照片与相机权限

- 相册权限：浏览照片、制作作品和查看「我的拼图」时使用。允许全部照片才能显示完整图库；只允许部分照片时，应用会显示权限提示，可管理已授权照片或打开系统设置。
- 相机权限：从相册左上角的相机入口拍照、拍摄证件照以及扫描文档时使用。不需要录音权限。
- 保存权限：导出图片时申请系统相册所需权限；拒绝后不能正常写入相册。

应用不请求照片定位权限。Android 编辑流程直接使用图库图片 URI，避免为了编辑图片读取无关的 EXIF 位置信息。

本地图片处理可以离线完成。如果 iOS 照片仅存于 iCloud，选取时仍可能需要联网下载到设备。扫描文件通过系统分享面板导出，分享目标是否需要联网取决于用户选择的其他应用。

## 3. 拼图与照片编辑操作

### 3.1 共用相册选择器

快速拼图、布局、自由拼图、长图拼接、编辑、九宫格及证件照复用应用内相册页面。照片按创建时间从新到旧显示，相册分页读取，每页 80 张；可切换系统相册及下拉刷新。

多图模式下，点击照片即选中并显示选择顺序，已选照片出现在底部缩略图区域。再次点击照片，或点击底部对应缩略图，可以取消选择。跨相册切换会保留本次选择。选择至少两张后「下一步」可用，作品中的初始照片顺序跟随选择顺序。

单图模式下，点击一张照片直接进入下一步，不经过多选确认。左上角「相机」可以拍摄新照片；证件照模式会进入专用拍照页面。

### 3.2 快速拼图与布局

**快速拼图路径：** 首页 → 快速拼图 → 选择 2–9 张照片 → 下一步 → 选画布比例与模板预览 → 拼图编辑 → 保存。

**布局路径：** 首页 → 布局 → 选择 2–9 张照片 → 下一步 → 查看上方大幅预览及下方布局缩略图 → 使用此布局 → 拼图编辑 → 保存。

两者使用同一套布局算法和拼图编辑器，差异主要在进入编辑前的模板选择界面。当前提供按照片数量生成的少量基础布局：

- 两张照片：左右拼接、上下拼接、主副构图。
- 三张及以上：整齐网格、突出第一张照片的主图布局、大图位于上方的杂志布局。
- 画布比例：1:1、4:5、4:3、2:1、3:4、2:3、9:16。

编辑画布时可以单指拖动子图片调整框内取景，双指缩放图片；拖动横向或竖向分隔线上的紫色醒目手柄可以联动调整相邻区域大小。各区域仍属于一个整体画布。布局切换后，分隔线按对应模板重新生成。

底部工具提供布局、比例、画框、背景、滤镜和纹理。背景有六种预设颜色，滤镜有原图、奶油、冷调、复古、清透，纹理有无、点点、斜纹。可选择照片边框及间距。这里的滤镜是本地颜色叠层效果，不是专业色彩曲线或 LUT 滤镜库。

保存时只输出组合画布，分隔线操作手柄不进入成品。该流程生成一张新图片，不覆盖原始照片。

### 3.3 单张照片编辑

**路径：** 首页 → 编辑 → 点选一张照片或拍照 → 照片编辑 → 保存。

| 工具 | 操作方法及当前范围 |
| --- | --- |
| 裁剪 | 拖动框内移动取景范围；拖动四条边或四个角改变范围；支持自由比例、1:1、4:5、2:1、3:4，确认后执行实际像素裁切 |
| 滤镜 | 原图、奶油、冷调、复古、清透五种基础效果 |
| 调整 | 亮度增减、图片放大/缩小、每次旋转 90°；亮度通过明暗叠层实现 |
| 文字 | 输入文字后添加到画布，支持多个文字图层，点击选中并拖动位置 |
| 贴纸 | 八种预设 Emoji 贴纸，点击添加，可选中和拖动位置 |
| 删除图层 | 点击「删除选中的文字 / 贴纸」移除对应图层 |

保存时隐藏文字和贴纸的选中标记。当前没有字体商城、复杂文字特效、贴纸商店或高级局部修图工具；Emoji 的实际外观会受到手机系统字体影响。

### 3.4 自由拼图

**路径：** 首页 → 自由拼图 → 选择 2–9 张照片 → 下一步 → 自由摆放 → 保存。

进入画布后，照片按初始位置排列，允许相互重叠。直接单指拖动子图片改变位置，双指捏合缩放、双指旋转；操作某张图片时会选中它并显示提示边框。无需先点击移动、缩放或旋转按钮。

可调整画布比例、背景、基础滤镜与纹理，也可添加一段显示于画布底部的说明文字。这段说明文字与单图编辑中的可拖动文字图层是不同的实现。保存时隐藏选中照片的紫色提示边框。

### 3.5 长图拼接

**路径：** 首页 → 长图拼接 → 按顺序选择 2–20 张照片 → 下一步 → 纵向长图预览 → 保存。

照片统一宽度，按各自宽高比顺序纵向拼接，不主动裁掉图片内容。可上下滚动查看，点击放大图标打开整体预览。导出捕获完整滚动内容，不只保存屏幕当前可见部分；画布左右贴边，避免将预览背景的黑边一起导出。

此入口目前采用纵向拼接，不提供横向拼接或截图重复区域自动去重。大量或很长的原图会按输出尺寸限制整体缩放。

### 3.6 九宫格切图

**路径：** 首页 → 九宫格 → 点选单张照片 → 移动、缩放、旋转取景 → 选择格数 → 下一步 → 预览与保存。

支持 3×1、3×2、3×3、3×4，即 3、6、9、12 格，默认 9 格。单指移动照片、双指缩放及旋转，切换格数会重置取景变换。

预览页面显示各格编号；点击编号可以保存该格，点击「全部保存」输出全部小图。编号顺序从左到右、从上到下。发布到社交平台时，需要按平台实际排布方式选择上传顺序，应用不会自动发布。

该功能是将一张照片切成多张图片，与首页尚未实现的「格子拼图」不是同一个业务。

## 4. 电子证件照

### 4.1 规格选择

「一寸照」「二寸照」进入对应规格说明页，可查看尺寸、拍照建议及示例指导，再选择「从相册选择」或「去拍照」。

「更多规格」支持分类浏览、按名称搜索和自定义尺寸。当前规格来自本地配置，不从服务端动态更新；「近期热门」显示的是本地规格集合，不是实时热度排行。

| 规格 | 像素宽×高 | 参考毫米宽×高 |
| --- | --- | --- |
| 一寸 | 295×413 | 25×35 |
| 二寸 | 413×579 | 35×49 |
| 小一寸 | 260×378 | 22×32 |
| 大一寸 | 390×567 | 33×48 |
| 小二寸 | 413×531 | 35×45 |
| 三寸 | 650×992 | 55×84 |
| 五寸 | 1051×1500 | 89×127 |
| 公务员考试 | 413×531 | 35×45 |
| 教师资格考试 | 295×413 | 25×35 |
| 中国护照 | 390×567 | 33×48 |
| 美国签证 | 602×602 | 51×51 |
| 社保证件照 | 358×441 | 30×37 |

自定义证件照的宽、高分别允许输入 100–3000 之间的整数像素。毫米显示按 300 DPI 换算。规格名称代表当前预设尺寸，不代表应用对各机构最新要求作了实时验证。

### 4.2 拍照与人像检测

从相册点选一张图片后进入检测；拍照路径提供前后摄像头切换、闪光灯、取景辅助线及拍照建议。拍摄后可「重拍」或「使用照片」，使用照片后进入同一检测流程。

流程为：图片归一化 → 检测人脸 → 判断人脸数量、位置和大小 → 按所选比例自动取景 → 进入编辑。

照片未检测到人脸、检测到多个人，或人脸大小及位置超出当前阈值时，会提示重新选择。检测是基本人像构图检查，不是身份认证，也没有实现完整的闭眼、遮挡、姿态、清晰度或官方证件照合规审核。正面、单人、均匀光照、清晰轮廓的照片通常更适合处理。

### 4.3 背景、美颜与美妆

进入编辑后默认使用蓝色背景，可切换「基础色」「高级色」「糖果色」，每组六种，共 18 种预设颜色。每次换色以原始处理输入重新合成，避免在上一次结果上反复叠加。

Android 使用随安装包内置的 ML Kit 人像分割模型，iOS 使用 Vision 人像分割。算法先估计人物前景，再替换背景，高置信度前景保留原色，对不确定边缘做柔和过渡；不采用全图颜色替换。

美颜、美妆提供「无、轻度、自然、明亮」四档，当前主要是限制在检测到的人脸区域内的轻度提亮和暖色修饰，不包含五官重塑、复杂磨皮或独立口红/眼妆生成。

人像分割属于概率识别。导出前应查看发丝、颈部及服装边缘；复杂背景、背景与衣服颜色相近、逆光或严重遮挡的照片可能仍需换图。检测通过不代表成品一定符合提交机构要求。

### 4.4 换正装

当前提供男装 14 款、女装 4 款，以及保留的童装 3 款 SVG 正装样式，还可选择「无」恢复不叠加服装。男装与女装使用用户提供的图片，经预处理成为透明 PNG 后随应用打包，使用时无需下载。

选择服装后，程序根据人脸位置尝试初始适配。在「电子照预览」中直接单指上下左右移动服装，双指缩放和旋转；点击「重新适配」恢复自动适配位置。排版照同步使用相同的服装及位置参数。

当前换装实现是**透明服装图层与人像的合成**，不是生成式换装，也没有完整的人体关键点、原衣服消除、布料变形或头发遮挡重建能力。不同体型、领口及拍摄角度需要手动调整，预览确认后再保存。

### 4.5 电子照、排版照与单独换底色

- 电子照：按所选规格的像素宽、高导出 JPEG，不加水印。
- 排版照：在 1800×1200 px 白色画布上按规格排列照片，电子照与排版照的背景、修饰及正装保持同步。页面提示按六寸相纸实际尺寸打印。
- 单独换底色：首页「证件照换底色」→ 相册单选 → 人像检测 → 换底色 → 保存。此入口不进入标准规格裁切，使用归一化后的原图比例及尺寸；高分辨率原图可能先被缩小，因此不保证保持原文件像素数量。

毫米和 300 DPI 用于规格说明、尺寸换算及打印参考；应以导出像素和打印软件设置为准，不应假定 JPEG 已写入特定 DPI 元数据。较大的自定义规格也需检查排版预览是否完整适合六寸画布。

## 5. 文件大小与像素尺寸工具

### 5.1 修改文件 kb 大小

首页 → 修改文件 kb 大小 → 从相册选择图片 → 调整宽、高及 JPEG 质量 → 查看生成预览与文件体积 → 保存到相册。

宽高可在「像素」「毫米」之间切换，毫米按 300 DPI 换算。质量范围为 5%–100%，修改后程序重新编码并显示真实输出体积。

当前通过尺寸和质量间接控制文件大小，**没有输入目标 KB 后自动精确压缩到该数值的功能**。如目标网站限制体积，应降低质量或尺寸，直到实际预览体积符合要求。宽、高可独立修改，没有自动锁定原图比例；改变比例可能造成图像拉伸。

### 5.2 修改文件 px 尺寸

首页 → 修改文件 px 尺寸 → 选择图片 → 点击关闭「试一试双指放大」蒙层 → 选择规格或自定义尺寸 → 单指移动、双指缩放取景 → 下一步 → 导出电子照片。

可按本地规格分类选择尺寸或自定义像素/毫米尺寸。裁切预览按目标比例显示，导出时裁切对应原图范围再缩放到指定像素，避免直接拉伸整张照片。该工具适用于任意单张图片，不要求先通过人脸检测。

两个工具的目标宽、高分别限制为 16–6000 px，总像素不超过 2400 万，输出格式为 JPEG；输入透明图片时不能保留透明通道。

## 6. 文档扫描（当前 Android）

首页「扫描」进入独立扫描会话，最多处理 50 页。当前扫描原生模块仅实现 Android；iOS 虽有共用页面，但没有对应扫描引擎，不能据此宣称 iOS 扫描已可用。

### 6.1 拍摄或导入

- 智能扫描：支持单页及多页；单页拍摄后直接进入编辑，多页模式可连续收集页面。
- 扫描书籍：支持单页及双页，双页可选择上下或左右分割，一张图片生成两页。
- 自动识边：开启时周期采样相机画面，显示识别到的纸张轮廓；需要用户点击拍摄，并非自动快门。关闭后仍可在后续页面手动裁切。
- 相册导入：可导入已有文档图片，按照当前单页、多页或书籍分割模式处理。

原图处理前会做方向归一化及尺寸控制，最长边超过 2600 px 时缩小，以控制移动设备内存使用。没有找到可靠纸张边缘时，可以手动确认取景范围。

### 6.2 编辑与页面管理

扫描页面支持拖动四角或边线调整裁切范围，带放大镜辅助对齐；通过四点透视变换将倾斜文档展开为矩形。可重新自动识别、恢复当前裁切或选择完整区域。

提供原图、清晰增强、去阴影、灰度、黑白五种效果；可将效果应用到所有页。还支持旋转、重拍当前页、前移/后移调整顺序、删除页面、继续添加图片及修改扫描名称。

预览界面支持全选/取消全选、逐页勾选和编辑，导出顺序跟随当前页面排列。退出扫描会提示保存未导出的页面；当前没有持久化的扫描工程列表，重新启动应用后不能依靠当前会话恢复未导出的扫描工程。

### 6.3 导出方式

| 导出方式 | 实际内容与使用方式 |
| --- | --- |
| PDF | 选中页按顺序写入文档，使用 A4 比例页面放置扫描图片；当前没有 OCR 可搜索文本层 |
| Word（DOCX） | 本机识别中英文，将识别文字按行写为可编辑内容，并附上对应扫描图；不会完整还原原文档的复杂版式或表格 |
| 长图 | 选中页统一宽度后纵向合成一张 JPEG，通过系统分享面板导出 |
| 保存到相册 | 每页单独保存到系统 PinPic 相册 |

PDF、Word 和扫描长图生成后打开系统分享面板，应选择合适的文件保存或分享目标。取消分享不代表文件已复制到用户指定目录。Word 的 OCR 结果需要校对，模糊文字、弯曲书页或复杂表格的效果可能不完整。

## 7. 保存位置与「我的拼图」

### 7.1 保存到系统相册

Android 图片导出通过系统媒体库创建/写入 `PinPic` 相册，通常可在图库的「相册 → PinPic」及公共 `DCIM/PinPic` 位置查看；具体路径显示取决于系统图库。程序会查询媒体库确认新文件已登记，再提示保存成功。

iOS 图片保存到系统「照片」，在具备相册读取能力时尝试归入 `PinPic` 相册；只有添加权限或无法管理相册时，仍保留已写入的系统照片，不将相册归类失败视为图片保存失败。

| 场景 | 当前输出尺寸规则 |
| --- | --- |
| 快速拼图、布局、单图编辑、自由拼图 | 宽 1200 px，高按画布比例计算，JPEG |
| 普通长图拼接 | 按整体比例缩放，目标宽不超过 1200 px、高不超过 16000 px，约 1200 万像素预算 |
| 九宫格 | 先生成宽 1200 px 的整体取景，再切片；当前每格 400×400 px |
| 电子证件照 | 所选规格的像素尺寸 |
| 证件照排版 | 1800×1200 px |
| 文件大小/像素尺寸工具 | 用户指定的有效目标尺寸 |
| 扫描长图 | 宽最多 1400 px，按约 28000 px 总高度预算缩小；过长导致宽不足 240 px 时提示改用 PDF 或减少页数 |

输出是扁平化成品，不保留可再次调整的独立图层。普通拼图导出按画布截图生成，不保证保持原图分辨率；原照片不会因为编辑和保存而被覆盖。

### 7.2 我的拼图

首页左上角设置 → 我的拼图，可查看系统 PinPic 相册中的作品，点击查看大图、下拉刷新，进入「管理」后多选删除。

删除操作会删除系统照片图库中的对应图片，并非只隐藏应用内缩略图。当前列表读取最新 120 张，没有后续分页加载。iOS 尚未创建专属相册时可能显示已授权的系统近期照片，此时禁止进入作品删除管理。

「我的拼图」是成品图库，包含由不同功能保存到该相册的图片，**不是历史工程库**。没有保存模板参数、图层、文字内容等工程数据，也没有一键恢复原编辑会话的功能。可以从普通相册入口重新选择成品作为新图片编辑。

### 7.3 常见使用问题

| 现象 | 建议检查 |
| --- | --- |
| 相册只看到部分图片 | 是否仅授权了部分照片；使用提示入口管理权限，或在系统设置中允许全部照片 |
| 多图模式无法下一步 | 是否至少选择两张照片，是否仍在读取图片 |
| 保存后暂时没找到图片 | 查看图库 PinPic 相册及最近照片，刷新图库；iOS 相册归类可能受读取权限影响 |
| 证件照检测失败 | 使用清晰的正面单人照片，避免多人、脸部过小、过度贴近画面边缘 |
| 换背景后边缘不自然 | 更换光照均匀、人物轮廓清楚、背景与衣服区分明显的照片 |
| 正装领口不匹配 | 在电子照预览中移动、缩放、旋转服装，或点击重新适配及更换模板 |
| 提示缺少证件照/扫描模块 | 使用包含原生模块的重新构建安装包，不能仅靠刷新 JavaScript 或 Expo Go 获得这些模块 |
| 导出 Word 与原稿版式不同 | 当前导出是识别文字及原扫描图，复杂排版需要在 Word 中进一步调整 |

### 8.3 自定义服装及图片资源

服装源文件位于 `assets/formalwear/men/`、`assets/formalwear/women/`，可以保留 PNG 和 WebP。实际运行目录为 `assets/formalwear/prepared/`，当前统一使用透明 PNG，处理了部分源图背景及多余透明留白。

资源处理脚本为 `scripts/prepare-formalwear.cjs`。在 macOS 上依赖 `sips` 解码 WebP，并通过 `pngjs` 处理透明背景及边界；部分模板包含按文件名设置的特定去背景规则，不是适用于任意衣服照片的通用智能抠图器。新增素材应逐张检查领口、透明背景和原衣服是否保留完整。

**仅放入图片文件不会自动出现在 APP 中。** 开发人员还需要：

1. 准备可用的透明服装图，并生成/确认 `prepared` 资源。
2. 在 `src/lib/formalwear.ts` 注册唯一 ID、标签、静态 `require()` 路径和准确宽高。
3. 检查 `IDPhotoPortrait` / `IDPhotoSuit` 的预览、手势与排版导出效果。
4. 运行素材检查并重新构建安装包；换装缩略图按注册目录读取。

静态引用保证服装随离线安装包打包；童装当前仍使用代码中的 SVG，不依赖新增童装图片。普通图标使用 `assets/pinpic-icon.png`，Android 自适应前景使用 `assets/pinpic-adaptive-icon.png`，背景颜色由 `app.json` 配置；其它图片文件是否参与界面或启动页必须检查引用及原生构建配置，不能仅根据文件名推断。

### 8.4 启动开发与验证

在项目根目录准备 Node.js/npm，安装锁文件中的依赖：

```sh
npm ci
npm run start
```

普通 JavaScript 页面可以用开发服务器调试，但证件照与扫描依赖自定义原生模块，**Expo Go 不包含这些模块**。验证完整业务必须使用含模块的原生开发构建或独立安装包。Web 预览也不能代替 Android/iOS 的权限、相机、原生识别及相册测试。

当前自动检查命令：

```sh
npm run typecheck
npm run lint
node --test tests/*.test.cjs
```

服装预处理及素材测试依赖 `pngjs`，当前 `package.json` 未将其显式列为直接依赖；当前工作环境可解析该包，新环境若提示缺失，需要先补齐并固定该工具依赖，再执行相应脚本或测试。已有 `prepared` 素材可以直接用于应用打包，不要求每次重新预处理。

本次文档整理时，类型检查、Lint 和现有 37 项测试通过。测试覆盖布局联动、图片及服装手势、分割完整性、相册写入确认、平台 URI 处理、尺寸换算、扫描裁切几何和服装透明素材；这些检查不代表 Android 原生引擎及 iOS 的完整真机流程已全部验证。

真机验收应重点检查首次相册加载及授权切换、所有入口的保存位置、长图无黑边、切图数量、换底色的人物边缘、正装预览与导出一致性，以及扫描的多页顺序、透视裁切和文件可打开性。

### 8.5 构建与版本维护

项目使用 EAS 云构建。当前 `eas.json` 的 `preview` 为内部安装分发，Android 输出 APK，签名凭据来源为本地；`production` 开启自动版本递增。构建需要联网、有效的 Expo 项目访问权限及相应签名材料。

```sh
# 登录具备当前项目权限的账号
npx eas-cli@latest login

# 生成独立 Android APK
npx eas-cli@latest build --platform android --profile preview --non-interactive

# iOS 构建；需先准备 Apple 签名与内部测试设备配置
npx eas-cli@latest build --platform ios --profile preview
```

Android `preview` 使用本地凭据时，要在本机准备与 `eas.json` 相匹配的 `credentials.json` 和 keystore；私钥、签名文件和密码不应提交到仓库。已有 APK 的覆盖升级应沿用同一签名。iOS 安装受 Apple 签名及分发方式限制，不能像 APK 一样任意安装到未配置的设备。

发布版本以 `app.json` 的应用版本、Android `versionCode` 等原生配置为准，`package.json` 中目前的 `1.0.0` 不是安装包显示版本。设置页当前将版本号写在页面中，发布时也需同步更新。

项目原生目录采用生成式配置，`android/`、`ios/` 未作为手工维护目录提交。业务代码在 `src/`，自定义原生代码在 `modules/`；配置原生行为通过 `app.json`、原生模块或配置插件完成，不要直接修改生成目录后误以为能长期保留。

升级或修改 Expo/React Native API 前，遵循 `AGENTS.md`，查阅对应 SDK 版本文档：<https://docs.expo.dev/versions/v57.0.0/>。EAS 构建说明见 <https://docs.expo.dev/build/introduction/>。
